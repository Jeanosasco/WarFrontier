# Contributing to WarFrontier

Thank you for helping build WarFrontier.

## Branches

- `main`: stable project state.
- `develop`: active integration branch.
- `feature/<name>`: new features or focused changes.
- `fix/<name>`: bug fixes.
- `release/<version>`: release preparation.

## Workflow

1. Create or select an issue before starting substantial work.
2. Branch from `develop`.
3. Keep commits focused and clearly named.
4. Add or update documentation when behavior changes.
5. Test the affected build or subsystem.
6. Open a pull request into `develop`.

## Commit style

Use concise prefixes when possible:

- `feat:` new feature
- `fix:` bug fix
- `docs:` documentation
- `chore:` maintenance
- `refactor:` internal restructuring
- `test:` test changes
- `build:` build system or dependencies

## Licensing and attribution

Do not submit code or assets unless you have the right to contribute them under terms compatible with this project.

When modifying imported Warzone 2100 files:

- preserve existing copyright headers;
- preserve license notices;
- document substantial changes;
- avoid removing attribution;
- identify the upstream file or commit when relevant.

Do not add models, textures, fonts, sounds, music, videos, logos, or other assets with unclear licensing.

## Quality expectations

Contributions should be readable, scoped, documented, and testable. Large changes should be divided into smaller pull requests whenever practical.

## Project identity

WarFrontier is an independent derivative project. New work should progressively establish original gameplay content, branding, factions, maps, missions, UI, audio, and narrative.
